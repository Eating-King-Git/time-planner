# 时间规划师 Time Planner：四象限待办与桌面时间管理

**按重要性决定先做什么，用时间块安排何时做，通过提醒与跨日延续跟进完成。**

时间规划师是一款开源的 Windows 桌面待办清单与时间管理工具，将**艾森豪威尔矩阵（重要/紧急四象限）**、**时间块安排（Time Blocking）**和**任务完成反馈**结合起来。输入中文任务后，可查看分类依据、补充截止时间与预计时长，将符合条件的事项排入当天空闲时段，并通过置顶窗口、桌面提醒和未完成任务延续持续跟进。

它适合同时处理课程、论文、会议、作业和个人事务的学生、研究者与个人工作者。支持今天、未来3天、未来7天和长期任务视图，让固定日程与待办工作在同一处查看。

**本地运行，无需账号、云同步或大模型 API。** 分类与排程采用可解释的规则，支持手动修正；任务保存在自己的电脑中。日常使用不产生模型 Token 费用。

**English overview:** Time Planner is an open-source, local-first Windows desktop task manager and daily planner. It combines the **Eisenhower Matrix**, **time blocking**, and **task completion feedback** with Chinese task input, rule-based daily scheduling, desktop reminders, an always-on-top window, and automatic carryover of unfinished tasks. It supports personal productivity, study planning, and research workflows without requiring an account or an LLM API. The interface is currently in Chinese.

## 如何把管理方法落实到日常安排

软件围绕“记录事项 → 明确要求 → 确定优先级 → 安排时间 → 确认完成”组织操作，将管理方法落实到每天可以使用的动作。

| 管理思路 | 软件中的实现 | 帮助解决的问题 |
| --- | --- | --- |
| 四象限优先级管理 | 根据影响、截止时间等信息评分，显示理由，允许手动调整重要/紧急标记 | 事情很多，不知道先做哪件 |
| 任务澄清 | 提示补充截止、预计时长和影响程度 | 只记下“做报告”，却没有明确执行条件 |
| 时间块安排 | 将符合条件的待办排入当天工作时段，考虑固定日程和午休 | 清单越来越长，却没有给任务留时间 |
| 缓冲与重点意识 | 默认采用20%的排程缓冲设置，最多标记3个关键结果 | 日程排得过满，难以判断当天重点 |
| 计划与执行反馈 | 提醒后由用户确认状态，当天已完成任务继续可见，未完成普通任务跨日延续 | 时间到了但事情没做完，跨天后容易遗漏 |

四象限比例用于指导时间分配；当前排程按优先级、时长和时间冲突安排，并不强制实现某一比例。任务澄清和执行反馈是本项目的工作流程设计，尚未提供完整的 GTD、PDCA、OKR 或项目管理系统。

## 设计亮点与实践创新

本项目的创新侧重于把常见管理方法组合成低操作成本的个人工作流程，具体体现在：

1. **从分类直接连接到行动。** 输入时即可看到所属象限与判断依据，保存后符合条件的任务参与当天排程，让优先级判断与时间安排相互衔接。
2. **把重要事项的时间投入放到眼前。** 四象限展示典型事项、建议比例与当天已排时长；课程和固定事件单独统计，帮助用户检查重要工作是否获得时间。
3. **延续任务，同时保留原截止。** 未完成普通任务进入后续日期，并标注延续天数；原截止不会被自动改晚，用户仍能看到逾期压力。已过去的课程按前缀规则排除。
4. **将确认结果纳入任务流程。** 信息不清楚时提示补充；待确认事项可以记录结果；到截止时提醒确认状态，帮助用户主动维护任务清单。
5. **用置顶小窗降低查看成本。** 在其他软件上方查看今日任务，可切换未来安排和长期清单，并调整窗口大小与缩放。
6. **规则可解释，本地可掌控。** 无需云端模型即可完成常见解析、分类与排程；规则开放在源码中，方便按个人工作方式继续修改。

以上是产品组合和交互上的实践创新，不代表提出了新的管理理论，也没有经过对照实验验证效率提升。评分、时间比例和排程结果可作为个人决策参考。

## 适合什么场景

- 课程、会议和个人任务混在一起，需要先看清哪些事情重要、哪些事情紧急。
- 希望工作时始终能看到今天的待办，同时让窗口占用较小空间。
- 希望查看明天和未来几天已经确定的安排，提前发现冲突。
- 希望未完成事项自动保留到后续日期，而不是跨天后被遗忘。

当前版本为 Windows 桌面 MVP，面向个人使用和继续开发。

## 功能

- 可置顶的小窗口，支持紧凑/完整视图、窗口大小调整和 75%–130% 界面缩放。
- 中文任务输入，支持常见相对日期、时长、截止时间和固定起止时间；信息不足时提示补充。
- 输入时预览四象限、评分依据和时间分配建议，支持手动调整重要性与紧急性。
- 今天、未来3天、未来7天和长期任务视图。
- 任务勾选完成后当天保留，次日从今日列表隐藏；未完成的过期普通任务持续延续。
- 标题以 `[课程]` 开头的过往课程不自动延续。
- 当日自动排程、时间冲突提示、桌面提醒和截止后状态确认。
- 标题以 `待确认：` 开头的事项可填写确认结果；结果会保存到任务说明。自由文本确认不会自动生成课程。

## 快速开始

### 直接使用便携版

如[Releases 页面](https://github.com/Eating-King-Git/time-planner/releases)提供便携包，完整解压 `TimePlanner-版本号-windows.zip`，双击其中的 `时间规划师.exe`。如果尚无可下载附件，请按下节从源码运行。其他 DLL、资源文件和 `locales` 文件夹需要一并保留，不能只复制 EXE。

便携版免安装、无需另装 Node.js；“便携”指程序文件，任务数据仍写入当前 Windows 用户的数据目录。当前发布构建面向 Windows x64。

### 从源码运行

在 Windows 上安装 Node.js 22 或更新版本，然后在项目目录运行：

```powershell
npm ci
npm start
```

首次启动没有预置个人任务或课表，直接输入自己的事项即可。

## 基本用法

1. 输入任务，例如 `明天下午3点前提交报告，需要1小时`。
2. 检查解析出的截止、时长和影响程度；缺失或不准确的信息可通过结构化字段补充。
3. 查看四象限预览和评分依据；必要时手动标记“重要”或“紧急”，然后保存。
4. 在“今天”和时间线中查看安排；切换“未来3天”或展开“未来7天”检查已知后续事项。
5. 完成后勾选方框。当天完成的任务继续保留，次日从今日列表隐藏；历史数据仍保存在本地。

课程或其他固定事件可填写“固定开始”和“固定结束”。为了避免把过去课程当作未完成工作继续结转，课程标题请使用 `[课程]` 前缀。

标题以 `待确认：` 开头的事项会显示“处理”入口。填写确认结果并提交后，说明被记录且事项标为完成。该操作只记录结果，不会把自由文本自动转换为新的课程或日历安排。

## 排程规则

按“重要且紧急 → 重要不紧急 → 紧急不重要”排序；低重要性且不紧急的任务不自动排程。默认工作时间为 09:00–18:00，午休为 12:00–13:30，预留20%的缓冲。长任务拆成时间块，固定事件参与冲突检查。

| 象限 | 判断含义 | 默认处理建议 |
| --- | --- | --- |
| 重要且紧急 | 影响较大，且需要尽快处理 | 优先执行 |
| 重要不紧急 | 对长期目标有价值，时间仍有余地 | 提前安排 |
| 紧急不重要 | 时间敏感，但对主要目标影响较小 | 限时处理，酌情委托 |
| 不重要不紧急 | 当前价值与时间压力都较低 | 暂缓或减少 |

重要性评分参考影响程度、阻塞/依赖和对他人的责任；紧迫性评分参考截止时间、不可逆时机和逾期/阻塞情况。默认60分为重要或紧急的判断阈值，手动标记优先。

四象限是一种管理方法；软件中的权重、时间比例和“置信度”是启发式规则，不代表经过实验验证的最优安排或统计概率。现有界面可调整任务字段和重要/紧急标记；底层评分权重与工作时段需要修改源码。

未来视图展示已知固定安排、已有时间块和截止事项；自动排程目前只计算今天。长期目标需要用户拆成具体行动或分次任务，软件不会自动规划整个项目。

### 未完成任务如何延续

普通任务有过去的截止、固定安排或历史排程记录且未完成时，会延续到今天，显示“昨日延续”或“已延续N天”。符合自动排程条件、且当天时间足够的任务会重新安排；原截止时间保留，不会因结转被自动推迟。

已过去的 `[课程]` 事项不结转。尚无日期或排程记录的任务不会凭空生成“昨日延续”标记。确认已完成的事项不会继续结转。

## 数据与提醒

Windows 默认数据目录为 `%APPDATA%\time-planner\`，包含 `tasks.json`、`settings.json` 和 `reminders.json`。备份前退出程序并复制该目录。任务数据不会随源码或便携包发布。

这些 JSON 文件为明文存储，当前版本没有数据库加密。不同版本使用同一数据目录，升级前建议备份；更换电脑时可在退出程序后复制该目录。公开仓库仅包含通用程序和测试示例，不包含个人姓名、课表或任务导入脚本。

提醒需要应用保持运行，且系统允许通知。当前没有账号、云同步或后台系统服务。普通保存提示两秒后消失；删除操作的撤销提示保留十秒。

## 当前限制

- 中文解析覆盖常见表达，不具备通用自然语言理解能力；复杂句子请检查并补充字段。
- 尚无跨多天自动优化、周期任务编辑器、日历同步、拖拽排程或移动端。
- 已知未来安排可以查看，节假日和调补课需要自己录入；程序不会自动获取学校或单位日历。
- 工作时间不足时会提示未能排入，不能保证所有任务都在截止前完成。
- 自定义固定事件除 `[课程]` 外仍可能结转，必要时请人工确认状态。
- 主要在 Windows 上验证，其他平台尚未验证；应用未运行时不会发出提醒。

## 测试与打包

```powershell
npm test
npm run package:win
```

Windows 打包会输出 `release/` 下的便携目录、便携 ZIP 和源码 ZIP。构建包使用本地已安装的 Electron 运行时，不会创建桌面快捷方式，也不会收集用户数据。发布前需在目标 Windows 系统验证。程序未做商业代码签名。

## 项目结构

```text
core/       日期解析、四象限分类、排程、任务延续与数据校验
renderer/   中文界面
tests/      Node.js 内置测试
scripts/    Windows 打包
main.js     Electron 主进程和消息接口
preload.js  渲染进程的受限接口
store.js    本地 JSON 存储
```

本项目是独立 Electron 应用，不是 Super Productivity 的分支。Electron 和其他依赖遵循各自许可证；便携包保留 Electron 附带的第三方许可文件。
